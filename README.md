# Список задач

Учебное приложение к модулю 3 дисциплины «Введение в специальность».
Автор: Коновалов Денис Александрович.

Приложение на Flask возвращает три задачи из памяти и позволяет получить
одну из них по идентификатору. База данных и пользовательский интерфейс не нужны.
Доступны только операции чтения; учебный набор данных задан в исходном коде.

## Установка и запуск

Требуется Python 3.12 или новее с модулем `venv` и `pip`.
Распакуйте архив и откройте терминал в каталоге `tasks-mvc`, где находится `main.py`.
Для установки зависимостей нужен доступ к PyPI.

Linux / macOS:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Windows (командная строка cmd.exe):

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python main.py
```

Если установлен более новый Python, замените `python3.12` или `py -3.12`
на команду запуска этой версии. Сервер доступен по адресу
`http://127.0.0.1:8000`. Для остановки нажмите `Ctrl+C`.
Это встроенный учебный сервер Flask, без режима отладки.

В `requirements.txt` зафиксированы версии Flask и его транзитивных зависимостей.
Для тестов используется `unittest` из стандартной библиотеки Python.

## Ручная проверка HTTP

Не закрывая сервер, откройте второй терминал и выполните:

```bash
curl -i http://127.0.0.1:8000/tasks
curl -i http://127.0.0.1:8000/tasks/1
curl -i http://127.0.0.1:8000/tasks/999
```

В PowerShell используйте `curl.exe` вместо `curl`.
Ключ `-i` показывает заголовки и статус HTTP вместе с телом ответа.

| Запрос | Статус | Ответ |
| --- | --- | --- |
| `GET /tasks` | `200 OK` | JSON-массив из трех задач |
| `GET /tasks/1` | `200 OK` | JSON-объект задачи с id 1 |
| `GET /tasks/999` | `404 NOT FOUND` | JSON-объект с описанием ошибки |

Содержимое ответа `/tasks` (пробелы и порядок ключей несущественны):

```json
[
  {"id": 1, "title": "Изучить MVC", "completed": true},
  {"id": 2, "title": "Создать HTTP-маршруты", "completed": false},
  {"id": 3, "title": "Проверить приложение", "completed": false}
]
```

Ответ `/tasks/1`:

```json
{"id": 1, "title": "Изучить MVC", "completed": true}
```

Ответ `/tasks/999`:

```json
{"error": "Ресурс не найден"}
```

Во всех трех случаях `Content-Type` — `application/json`.

## Автоматизированная проверка

Из корня проекта, в активированном виртуальном окружении:

```bash
python -m unittest discover -s tests -v
```

Два smoke-теста проверяют HTTP-статусы, тип содержимого и структуру JSON:
список задач, существующую задачу и отсутствие задачи.
Ожидаемый итог: `Ran 2 tests` и `OK`.
Тестовый клиент Flask выполняет запросы внутри процесса; отдельный сервер
для этих тестов запускать не нужно.

## Разделение ответственности и MVC

**Model — `app/models.py`.** Неизменяемая сущность `Task` содержит
`id`, `title` и `completed`. В этом же модуле находятся учебные данные,
получение списка и поиск по идентификатору. Если задача не найдена,
`get_task` возвращает `None`. Модель не импортирует Flask, не знает
про HTTP-статусы и не формирует JSON.

**Controller — `app/routes.py`.** Обработчики принимают запрос, вызывают
функции модели и передают результат в слой представления. Для отсутствующей
задачи обработчик вызывает `abort(404)`: преобразование `None` в HTTP-ошибку
относится к HTTP-слою, а не к модели. Данные задач в обработчиках не хранятся.

**View — `app/presentation.py` и `jsonify` Flask.** Функция `task_to_dict`
задает поля ответа клиенту, а `jsonify` сериализует словарь или список
в JSON и задает тип содержимого ответа. Правил поиска задач здесь нет.
Общий JSON-ответ для HTTP 404 задан в обработчике ошибок в `main.py`.

**Точка входа — `main.py`.** Функция `create_app` создает приложение,
подключает Blueprint с маршрутами и обработчик 404. При выполнении
`python main.py` запускается сервер. При импорте в тестах сервер не запускается.

Flask не навязывает классическое MVC. В его терминологии функции,
привязанные к маршрутам, называются *view functions*, но в данном проекте
они выполняют обязанности контроллера. Роль представления выполняют
формирование словаря и JSON-сериализация, а не HTML-шаблоны.
Поэтому архитектурные роли описаны по ответственности, а не по названию
компонентов фреймворка. Отдельные каталоги `controllers/` и `views/` не нужны.

## Путь запроса

Для `GET /tasks/1` сервер передает запрос приложению Flask. Маршрутизатор
находит `/tasks/<int:task_id>`, преобразует идентификатор в число и вызывает
`show_task(1)`. Обработчик получает `Task` через `get_task(1)`, передает его
в `task_to_dict`, затем вызывает `jsonify`. Клиент получает JSON и HTTP 200.
Для `/tasks/999` модель возвращает `None`; обработчик инициирует HTTP 404,
а зарегистрированный обработчик ошибки формирует JSON с полем `error`.
